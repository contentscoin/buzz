# FMG Buzz 모바일 1.0.0

공식 Android Buzz와 함께 설치하는 FMG 커스텀 앱입니다.

## 설치 및 기존 계정 연결

1. `FMG-Buzz-1.0.0-arm64.apk`를 Android 휴대폰으로 옮겨 설치합니다.
2. 기존 데스크톱 Buzz에서 FMG 커뮤니티를 선택하고 **Settings → Mobile → Start pairing**으로 기기 페어링 QR을 엽니다.
3. 휴대폰의 **FMG Buzz → 기존 계정 QR 스캔**으로 해당 QR을 스캔하고, 양쪽의 확인 절차를 완료합니다.
4. 홈에서 기존 FMG 채널과 대화를 열고, 하단 **FMG**에서 **작업 목록 / 결과 문서**를 선택합니다.

커뮤니티 초대로 새 계정을 생성하면 기존 소유자 계정을 이어 쓰는 것이 아닙니다.
기존 계정의 기기 페어링을 사용해야 같은 서명 신원과 서버 대화를 불러옵니다.
공식 앱을 제거하거나 데이터를 지울 필요가 없습니다. 공식 앱에만 저장된 미전송
초안·미전송 첨부·개인 설정은 공식 앱에 남으며 자동 복사되지 않습니다.

## 메뉴

| 메뉴 | 제공 기능 |
| --- | --- |
| 작업 목록 | 현재 FMG 소유자에게 조회 가능한 최근 25개 작업, 상태, 역할, 모델, 요청 effort, 새로 고침 |
| 작업 상세 | 작업 지시문, 실행 ID, 저장소 결속이 기록된 경우 저장소·브랜치, 실제 모델, 에이전트 출력 |
| 결과 문서 | 원 제안 계정이 소유자에게 접근을 허용한 문서 목록, 20개씩 페이지 이동 |
| 문서 상세 | 불변 Markdown 버전 선택, UTF-8·크기·SHA-256 검증, 실행 근거, 별도의 원본 출력 조회 |

작업을 승인·재실행하는 버튼은 이 첫 모바일 버전에 없습니다. 닷 제어 모드와
Hostinger 실행 경로는 기존 서버 설정을 사용합니다. 모바일 채팅·멘션은 기존
Buzz 채널 기능을 사용합니다. `dispatching`은 실행 요청 상태이며 실제 완료를
뜻하지 않습니다. `cancel_requested`는 종료 확인이 아닙니다.

## 계정·대화·접근 경계

- 설치 ID: `xyz.fmg.buzz.mobile`. 공식 앱 `xyz.block.buzz.mobile`과 앱 데이터,
  Android 키 저장소, 업데이트 서명이 분리됩니다. 앱 이름과 F 아이콘도 다릅니다.
- FMG 커스텀 빌드는 `fmgbuzz://`만 Android 앱 링크로 등록합니다. 공식 앱의
  `buzz://` 링크 등록을 가로채지 않습니다. 기존 QR 페어링 내용은 스캐너로 읽습니다.
- 작업·문서는 `https://fmg.communities.buzz.xyz`와 현재 배포의 소유자·Gateway
  공개키에 결속합니다. BD에서 FMG 데이터를 대신 표시하지 않습니다.
- 같은 계정의 NIP-42 릴레이 인증 및 서명된 kind 24200 / NIP-44 요청을 사용합니다.
  수신 서명, 작성자, 대상 태그, 요청 UUID, 작업, 문서 버전, 릴레이와 응답 시각을 검증합니다.
- 서버의 기존 소유자 문서 위임(`Desktop document access`)은 플랫폼명이 아닌
  소유자 공개키와 커뮤니티·Gateway·원 제안 연결로 검증되는 암호화 조회 경로입니다.
  모바일도 같은 소유자 경로로 읽으며 접근 허용을 새로 생성하거나 확대하지 않습니다.
  따라서 저장 문서가 있어도 해당 작업의 위임이 꺼져 있으면 모바일 목록에 보이지 않습니다.
- 문서 열기·버전 변경·원본 조회 때 서버에서 접근을 다시 확인합니다. 열린 문서는
  90초마다 재조회하며 앱이 백그라운드에 가거나 연결이 끊기면 내용을 숨깁니다.
- 승인 암호, OAuth 토큰, Supervisor operator 토큰, Telegram 토큰, 서버 개인키,
  Android 서명키는 APK와 소스에 포함하지 않습니다. 개인 신원은 기존 페어링에서만 받습니다.

## 오프라인과 보관

최근 작업 목록 한 개만 OS 암호화 저장소에 최대 32KiB로 보관합니다. 소유자·릴레이·
Gateway가 일치하고 7일 미만인 경우에만 오프라인 표시하며 조회 시각과 캐시임을
명시합니다. 현재 실행 상태나 권한 확인으로 취급하지 않습니다. 권한 거부 응답 시
목록 캐시를 제거합니다. 문서 본문과 작업 상세는 디스크 캐시에 저장하지 않습니다.
문서는 32KiB, 버전은 최대 20개이며 서버 한도를 그대로 적용합니다.

## 빌드

저장소의 Hermit 환경 및 핀 Flutter 3.41.7이 기본입니다. Windows에서 Hermit이
지원되지 않는 경우 호환되는 별도 Flutter SDK를 지정할 수 있습니다. 첫 Windows
설치본은 이미 준비된 Flutter 3.47.5 / Dart 3.13.4 및 JDK 17로 빌드했습니다.
다른 Flutter를 쓰면 SDK 의존성에 따른 lockfile 차이를 함께 검토해야 합니다.

전용 Android 릴리스 서명키는 저장소 밖에서 보관하고 아래 환경변수로만 전달합니다.
동일한 앱 ID와 서명키를 유지하고 빌드 번호를 올려야 기존 FMG 설치를 업데이트합니다.

```powershell
# 환경에 전용 서명키 설정이 준비된 상태에서 실행
# BUZZ_ANDROID_UPLOAD_KEYSTORE_PATH / BUZZ_ANDROID_UPLOAD_KEYSTORE_PASSWORD
# BUZZ_ANDROID_UPLOAD_KEY_ALIAS / BUZZ_ANDROID_UPLOAD_KEY_PASSWORD
./scripts/build-fmg-mobile.ps1 -FlutterSdk <Flutter-SDK-경로> -BuildNumber 1
```

`FMG_CUSTOM=true` 한 설정을 Gradle과 Dart가 함께 읽습니다. 일반 빌드는 공식 앱
ID와 기존 메뉴를 유지합니다. FMG 빌드에서도 Android namespace는 기존 네이티브
플러그인 패키지로 유지하되 applicationId만 별도로 지정합니다.

## 남은 확인

실제 휴대폰에 이 새 APK를 설치하고, 기존 계정 페어링 → 기존 대화 표시 → 작업
목록 → 접근이 허용된 결과 문서 표시를 확인해야 합니다. USB 장치는 현재 연결되지
않아 휴대폰 설치를 자동으로 수행하지 못했습니다. 이전 공식 모바일의 채팅 왕복
확인은 이 새 설치본의 실행 검증을 대신하지 않습니다. iOS 설치본은 포함하지 않습니다.
