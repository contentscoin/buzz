# FMG Buzz 모바일 1.2.1

공식 Android Buzz와 함께 설치하는 FMG 커스텀 앱입니다.

## 설치 및 기존 계정 연결

1. `FMG-Buzz-1.2.1-arm64.apk`를 Android 휴대폰에서 설치합니다. 이미 페어링한 FMG 1.0.0/1.1.0이 있으면 제거하지 않고 덮어 업데이트합니다.
2. 기존 데스크톱 Buzz에서 FMG 커뮤니티를 선택하고 **Settings → Mobile → Start pairing**으로 기기 페어링 QR을 엽니다.
3. 휴대폰의 **FMG Buzz → 기존 계정 QR 스캔**으로 해당 QR을 스캔하고, 양쪽의 확인 절차를 완료합니다.
4. 홈에서 기존 FMG 채널과 대화를 열고, 하단 **FMG**에서 **작업 목록 / 결과 문서**를 선택합니다.

커뮤니티 초대로 새 계정을 생성하면 기존 소유자 계정을 이어 쓰는 것이 아닙니다.
기존 계정의 기기 페어링을 사용해야 같은 서명 신원과 서버 대화를 불러옵니다.
공식 앱을 제거하거나 데이터를 지울 필요가 없습니다. 공식 앱에만 저장된 미전송
초안·미전송 첨부·개인 설정은 공식 앱에 남으며 자동 복사되지 않습니다.

## 모바일 관리 사용 순서

1. PC에 companion `Buzz 0.5.26-fmg.25`를 설치하고 같은 소유자 계정의 FMG 커뮤니티를 선택합니다.
2. 휴대폰 **FMG → 에이전트 관리 / 프로젝트 관리**를 열면 PC 연결을 자동 확인합니다. 실패하면 원인 문구와 **PC 연결 / 새로 고침**을 표시합니다.
3. 에이전트의 **수정** 또는 프로젝트의 **+**를 사용합니다. 모델/effort는 PC 실행기가 반환하는 선택지를 사용합니다.

PC의 Buzz가 실행되어 있어야 PC 에이전트·작업 공간을 관리할 수 있습니다.
Hostinger 작업/문서 조회와 OpenClaw 채팅은 기존 서버 연결을 사용합니다.
PC 전체 중지는 PC 로컬 FMG 에이전트만 대상으로 합니다. OpenClaw 서버 중지는 포함하지 않습니다.
소유자 페어링 서명으로 연결하므로 관리 요청마다 별도 승인 비밀번호를 입력하지 않습니다.

현재 자신의 소유자 키가 작성한 프로젝트의 정보·저장소를 편집할 수 있으며,
다른 작성자의 프로젝트는 조회와 참여 권한에 따른 할 일·검토 기능만 가능합니다.
PC 설정 전체, 외부 Git 호스팅 관리, raw Git 터미널과 모든 PC 기능의 모바일 복제는 포함하지 않습니다.
브랜치/병합은 FMG 커뮤니티 저장소에 적용하며 PC의 기존 Git 권한과 커밋 검사를 사용합니다.

### 변경 응답이 끊긴 경우

- 변경 전 요청 UUID·내용 해시·대상 PC를 기록합니다. **이전 요청 확인**은 원래 작업을 조회합니다.
- PC에 미수신이 확인된 경우에만 같은 UUID를 다시 전송할지 사용자가 선택합니다.
- 완료 여부가 불명확하면 현재 PC 설정을 확인한 후 대기를 해제합니다. 성공으로 표시하거나 자동 재실행하지 않습니다.
- 편집 초안은 휴대폰 OS 암호화 저장소에 최대 20개/전체 100KB를 보관합니다.
  다른 기기의 수정과 충돌하면 다시 조회해야 하며 오래된 초안으로 덮어쓰지 않습니다.
- PC는 소유자·커뮤니티별 암호화 journal에 최대 200개/2MB를 저장합니다.
  완료 기록은 7일, 미확인 기록은 자동 삭제하지 않습니다. 저장 실패 시 새 변경을 시작하지 않습니다.
- 요청/응답은 서명·UUID·기기 ID·릴레이·시각을 검증하는 NIP-44 암호화 NIP-78 데이터입니다.
  PC 환경변수, 비밀키, 실행 인수의 인증정보와 로컬 경로는 전달하지 않습니다.
- 프로젝트 head와 native agent revision을 검사합니다. Nostr 교체 가능 이벤트의
  동시 작성은 DB 원자적 CAS가 아니므로 최종 새로 고침으로 반영을 확인합니다.

작업을 승인·재실행하는 버튼은 이 첫 모바일 버전에 없습니다. 닷 제어 모드와
Hostinger 실행 경로는 기존 서버 설정을 사용합니다. 모바일 채팅·멘션은 기존
Buzz 채널 기능을 사용합니다. `dispatching`은 실행 요청 상태이며 실제 완료를
뜻하지 않습니다. `cancel_requested`는 종료 확인이 아닙니다.

## 앱 자동 업데이트

1. 최초 한 번은 FMG 1.2.1을 기존 앱 위에 설치합니다. 이전 버전에는 업데이트 기능이 없습니다.
2. 이후 시작/앱 복귀 시 새 버전을 자동 확인하고 Wi-Fi에서는 자동 다운로드합니다.
   자동 확인은 6시간마다 한 번이며 **FMG → 다시 확인**으로 바로 조회할 수 있습니다.
3. **다운로드한 업데이트 설치**를 누르면 Android 설치 화면으로 이어집니다.
   최초에는 이 앱의 설치 허용을 켜고 돌아와 설치를 다시 누릅니다.
4. **자동 업데이트 확인** 스위치로 자동 확인/다운로드를 끌 수 있습니다.

PC .25도 시작/6시간마다 FMG 서명 업데이트를 확인·다운로드하며 앱의 업데이트 버튼으로
적용/재시작합니다. 작업 중인 에이전트를 임의로 재시작하지 않도록 적용은 사용자가 누릅니다.
앱 업데이트에는 Buzz 작업 승인 암호를 사용하지 않습니다.

설치 파일은 전용 HTTPS 업데이트 채널에서 제공하며 앱 ID·증가하는 빌드 번호·SHA-256과
기존 Android 서명을 확인합니다. PC는 Tauri 업데이트 서명을 검증합니다.
다운로드가 끊기면 부분 파일을 제거하고 재시도하며 다운로드 완료 파일은 재시작 후 재검증합니다.
기존 계정·기기 페어링·작성 초안을 삭제하지 않습니다.

## 계정·대화·접근 경계

- 설치 ID: `xyz.fmg.buzz.mobile`. 공식 앱 `xyz.block.buzz.mobile`과 앱 데이터,
  Android 키 저장소, 업데이트 서명이 분리됩니다. 앱 이름과 F 아이콘도 다릅니다.
- FMG 커스텀 빌드는 `fmgbuzz://`만 Android 앱 링크로 등록합니다. 공식 앱의
  `buzz://` 링크 등록을 가로채지 않습니다. 기존 QR 페어링 내용은 스캐너로 읽습니다.
- 작업·문서는 `https://fmg.communities.buzz.xyz`와 현재 배포의 소유자·Gateway
  공개키에 결속합니다. BD에서 FMG 데이터를 대신 표시하지 않습니다.
- 같은 계정의 NIP-42 릴레이 인증 및 서명된 kind 24200 / NIP-44 요청을 사용합니다.
  수신 서명, 작성자, 대상 태그, 요청 UUID, 작업, 문서 버전, 릴레이와 응답 시각을 검증합니다.
- 서버의 기존 소유자 문서 위임(`Desktop document access`)은 플랫폼명이 아닌
  소유자 공개키와 커뮤니티·Gateway·원 제안 연결로 검증되는 암호화 조회 경로입니다.
  모바일도 같은 소유자 경로로 읽으며 접근 허용을 새로 생성하거나 확대하지 않습니다.
  따라서 저장 문서가 있어도 해당 작업의 위임이 꺼져 있으면 모바일 목록에 보이지 않습니다.
- 문서 열기·버전 변경·원본 조회 때 서버에서 접근을 다시 확인합니다. 열린 문서는
  90초마다 재조회하며 앱이 백그라운드에 가거나 연결이 끊기면 내용을 숨깁니다.
- 승인 암호, OAuth 토큰, Supervisor operator 토큰, Telegram 토큰, 서버 개인키,
  Android 서명키는 APK와 소스에 포함하지 않습니다. 개인 신원은 기존 페어링에서만 받습니다.

## 오프라인과 보관

최근 작업 목록 한 개만 OS 암호화 저장소에 최대 32KiB로 보관합니다. 소유자·릴레이·
Gateway가 일치하고 7일 미만인 경우에만 오프라인 표시하며 조회 시각과 캐시임을
명시합니다. 현재 실행 상태나 권한 확인으로 취급하지 않습니다. 권한 거부 응답 시
목록 캐시를 제거합니다. 문서 본문과 작업 상세는 디스크 캐시에 저장하지 않습니다.
문서는 32KiB, 버전은 최대 20개이며 서버 한도를 그대로 적용합니다.

## 빌드

저장소의 Hermit 환경 및 핀 Flutter 3.41.7이 기본입니다. Windows에서 Hermit이
지원되지 않는 경우 호환되는 별도 Flutter SDK를 지정할 수 있습니다. 첫 Windows
설치본은 이미 준비된 Flutter 3.47.5 / Dart 3.13.4 및 JDK 17로 빌드했습니다.
다른 Flutter를 쓰면 SDK 의존성에 따른 lockfile 차이를 함께 검토해야 합니다.

전용 Android 릴리스 서명키는 저장소 밖에서 보관하고 아래 환경변수로만 전달합니다.
동일한 앱 ID와 서명키를 유지하고 빌드 번호를 올려야 기존 FMG 설치를 업데이트합니다.

```powershell
# 환경에 전용 서명키 설정이 준비된 상태에서 실행
# BUZZ_ANDROID_UPLOAD_KEYSTORE_PATH / BUZZ_ANDROID_UPLOAD_KEYSTORE_PASSWORD
# BUZZ_ANDROID_UPLOAD_KEY_ALIAS / BUZZ_ANDROID_UPLOAD_KEY_PASSWORD
./scripts/build-fmg-mobile.ps1 -FlutterSdk <Flutter-SDK-경로> -BuildNumber 2
```

`FMG_CUSTOM=true` 한 설정을 Gradle과 Dart가 함께 읽습니다. 일반 빌드는 공식 앱
ID와 기존 메뉴를 유지합니다. FMG 빌드에서도 Android namespace는 기존 네이티브
플러그인 패키지로 유지하되 applicationId만 별도로 지정합니다.

## 남은 확인

기존 FMG 모바일의 페어링은 사용자가 완료했다고 알려주셨습니다. 새 1.2.1 설치 후
에이전트 수정·전체 중지·프로젝트 생성이 PC에 반영되는 실제 기기 확인은 아직 남아 있습니다.
정적 분석·컴파일과 실제 기기 동작을 구분합니다. iOS 설치본은 포함하지 않습니다.

## 1.2.1 연결 복구

- PC .25는 초기화가 겹칠 때 이전 수신기가 종료된 뒤 새 수신기를 엽니다. 커뮤니티 전환 때 대기 중인 초기화를 취소합니다.
- PC 발견은 15초로 제한하고, 미확인 변경이 없을 때만 오래된 기기 ID를 다시 발견합니다. 최대 30초 후 응답 부재를 표시합니다.
- 이전 요청이 없다는 로컬 기록만으로 PC 연결을 성공으로 표시하지 않습니다.
- 계정과 커뮤니티가 바뀌면 이전 목록과 제어를 숨깁니다. 기존 미확인 변경은 자동 재실행하지 않습니다.
