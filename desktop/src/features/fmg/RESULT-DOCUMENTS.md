# B09/B10 첫 코드 구현

## 작업 관리 화면 보완 (.20)

- 작업 ID·제안 해시·역할·모델·effort 검색과 상태별 필터를 제공한다.
  개수와 검색은 현재 커뮤니티에서 조회한 최근 25건에만 적용된다. 전체 원장 수가 아니다.
- schema 4 작업은 서버가 이미 반환하는 고정 저장소·브랜치·기준 commit·작업 공간
  결속을 검증하고 표시한다. 역할/브랜치/제안 계정이 맞지 않으면 상세 조회가 실패한다.
  연결 정보는 승인 대상이며 현재 checkout이나 실행 완료를 증명하지 않는다.
- 승인 대기는 승인·취소 명령, 실행 대기/요청은 취소 명령, `needs_reconcile`은
  복구 명령을 보여준다. 정확한 작업 UUID와 전체 제안 해시를 복사한다.
  명령 실행은 소유자의 직접 Telegram 전송으로 처리하며 Desktop에서 실행하지 않는다.
- 모바일용 작업 조회 요약은 미리보기 확인 후 명시적으로 복사한다. 현재 상태,
  요청/기록 모델·effort·저장소·실행 ID·조회 시각 및 최대 500자 응답을 포함한다.
  불확실/취소 요청/잘린 응답은 그대로 표시한다. 자동 게시나 불변 문서 저장이 아니다.
- Hostinger main의 예약 제안 계정은 원래 OAuth 제안 계정의 문서 권한을 빌리지 않는다.
  현재 이 계정에 문서 저장 계약이 없으므로 지원되지 않는 저장 메뉴 대신 안내한다.
- 커뮤니티·소유자·서버 에이전트 전환은 기존 키/취소 경계를 유지한다. 검색과 복사는
  새로운 서버 조회 권한, 메시지 전송 권한, 작업 실행 권한을 추가하지 않는다.

## 사용 경로

FMG 센터 → **작업 목록·결과·문서 열기** → 작업 선택 →
**Markdown 초안·문서**. 보관 문서는 같은 화면의 **저장된 결과 문서**에서
조회한다. 최근 25개 작업에 없는 문서도 찾을 수 있다.

작업 서버 0.7.0과 FMG Computer 0.3.0을 함께 적용해야 한다.
이 문서는 코드 사용법이며 현재 설치된 앱에 메뉴가 나타난다는 확인은 아니다.

## 접근 허용

원래 작업을 제안한 GPT dot의 FMG Buzz Tasks 연결에서 먼저
`fmg_buzz_get_document_desktop_access`로 revision을 조회한 뒤 다음 도구를
호출한다. 아래 값은 계약 예시이며 실제 요청을 전송하지 않았다.

```json
{
  "task_id": "작업 UUID",
  "enabled": true,
  "expected_revision": 0
}
```

도구: `fmg_buzz_set_document_desktop_access`.
철회는 최신 revision을 조회하고 `enabled:false`로 호출한다.
다른 제안 연결은 허용할 수 없으며 소유자·커뮤니티·Gateway가 달라지거나
원 제안 연결의 인증이 만료·철회되면 Desktop도 접근하지 못한다.
문서 허용은 작업 실행 승인이 아니다.

## 저장과 복구

- 원본은 검증된 성공 종료 증거에 연결된 보관 요약이다. 전체 모델 출력이라고
  표시하지 않는다. 큰 원본을 초안 한도에 맞춰 자동 잘라내지 않는다.
- Markdown은 32KiB 이내, 문서는 최대 20개 버전이다.
- 서버 전송 전에 요청 UUID와 원래 내용을 자기 신원 키로 암호화해 IndexedDB에
  원자적으로 보관한다. 평문 초안을 localStorage에 쓰지 않는다.
- 암호화 조각에는 범위·버전·순서·전체 해시를 묶어 다른 기록과 혼합하지 못하게
  한다. 서버 조회 결과도 SHA-256·UTF-8 길이·작업·문서·버전을 검증한다.
- 응답이 없으면 **저장 결과 확인**, 기록이 없으면 **같은 요청으로 재시도**한다.
  새 작업이나 새 저장 UUID를 자동 생성하지 않는다.
- 충돌이면 **최신 버전·충돌 비교**에서 최신 내용을 읽고, 내 초안을 유지한 채
  최신 버전을 기준으로 다음 저장을 준비한다. 자동 덮어쓰기는 없다.
- 초안은 800ms 후 로컬 보관을 시도하고 정상 닫기 전에 보관 완료를 기다린다.
  강제 종료·즉시 계정 전환 전에는 보관 완료 표시를 확인해야 한다.
- 로컬 한도는 범위당 20개, 앱 전체 100개 초안이다. 서버에서 동일 내용을
  확인했고 미확인 요청이 없으면 **확인된 로컬 보관 정리**로 공간을 비운다.
  서버 문서와 불변 버전은 삭제하지 않는다.
- 로컬 보관이 실패하면 화면과 초안을 유지한다. 명시적인 버리고 닫기 동작도
  제공하며 기존 서버 문서나 미확인 요청의 영속 기록을 지우지 않는다.

## 구현 확인 범위

소스의 타입·구문·빌드 확인과 실제 사용 경로는 구분한다.
실제 성공 작업 저장, 응답 유실·동시 저장·재시작·다른 신원 접근의 실행 검증,
Hostinger 배포, Desktop 설치 및 모바일 화면은 별도 작업이다.
기존 제안·승인·모델/effort 설정을 변경하거나 모델 작업을 실행하지 않는다.

### 소스 확인 기록

- Desktop TypeScript 검사 통과.
- Desktop OSS/내부 프런트엔드 빌드 및 기존 산출물 계약 확인 통과.
- 수정한 TypeScript/React/플러그인 소스의 Biome 검사 통과.
- FMG Computer 번들 빌드 및 작업 서버 Python 구문 분석 통과.
- 전체 Desktop 파일 크기 검사는 기존 `AgentInstanceEditDialog.tsx`의
  1,237줄이 기준 1,221줄을 초과하여 실패했다. 이 파일은 이번 변경에 포함되지
  않으며 새 문서 기능 파일은 1,200줄 이내다.
- 테스트를 추가하거나 실행하지 않았다. 실제 저장·충돌·재시작·접근 차단의
  동작 확인은 위 소스 검사와 별도로 남아 있다.

서버 메타데이터의 `saved_at`은 Unix 초, 원본 근거의 `verified_at`은 Gateway
검증 시각의 Unix 밀리초다. 원본 검증 시각을 실행 종료 시각으로 바꾸지 않는다.
